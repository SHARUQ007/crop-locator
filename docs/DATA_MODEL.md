# CropLocator mock database

All numbers and AEZ assignments are seeded synthetic examples, generated by `scripts/generate-mock-db.py` with random seed 42. They are neither SBSF model outputs nor FAO GAEZ estimates.

## Entities

- `crops`: 6 species, identity, category, season, screening ranges and synthetic economic baselines.
- `aezs`: 10 illustrative environmental classes. A spatial cell references its classification; an AEZ is not a 1 km cell and its colour is not a suitability score.
- `locations`: 24 named sample clusters across 10 countries. Each has 36 cells, approximately 36 km² / 3,600 ha. They are not complete district coverage.
- `cells`: 864 distinct approximately 1 × 1 km cells. Each has `locationId`, `aezId`, local geographic extent, centre, soil metrics and terrain values. A projected CRS should be used for production equal-area or exact 1,000 m grid construction.
- `periods`: baseline 2021–2025; 2030s 2026–2045; 2050s 2046–2065.
- `observations`: 155,520 crop-cell-context records. Baseline records use `historical`; future records use either `ssp245` or `ssp585`. Each context also includes local main season / Kharif / Rabi and rainfed/irrigated. Management level is held fixed in this demo.
- `sources`: synthetic environment and synthetic crop-requirement versions. Every raw observation references both and a model version.
- `summaries`: 4,320 location-context aggregates derived from raw observations, never separately authored numbers.

## Unique observation key

```
cellId + cropId + periodId + scenarioId + season + waterRegime
```

The production key should also include management regime, model version and any variety/trait profile where these alter model inputs. Climate baseline/projection period must remain separate from a specific growing season and observation date.

## Observation measures

| Measure                   | Unit / meaning                                                     |
| ------------------------- | ------------------------------------------------------------------ |
| `suitability`             | synthetic 0–100 environmental fit index                            |
| `confidence`              | synthetic 0–100 evidence/model confidence index; not a probability |
| `yieldTHa`, `yieldRange`  | tonnes / hectare; synthetic central estimate and low/high range    |
| `annualRainfallMm`        | mm / year, period average                                          |
| `meanTemperatureC`        | °C, period average                                                 |
| `supplementalWaterMm`     | illustrative supplemental water proxy; not a water allocation      |
| `heatRisk`, `droughtRisk` | synthetic 0–100 exposure indices                                   |
| `inputCostINRHa`          | INR / hectare / growing season                                     |
| `priceINRTonne`           | INR / tonne; not a live price                                      |

## Data delivery

`data/mock-db.json` contains the complete dataset. `public/data/mock-db.json.gz` is the gzip-compressed downloadable copy. `data/catalog.json` contains entities and precomputed location summaries used in the UI. Thirty files in `public/data/observations/` provide crop-period-scenario slices, loaded only when needed for cell inspection.

The generator is the source of truth. Regenerating reproduces all datasets. `scripts/validate-data.py` checks referential integrity, composite uniqueness, complete combinations, bounds, slice counts and aggregate consistency.

## User state

Frontend projects, notes, scenario assumptions, members and user evidence use namespaced `localStorage` keys. They are separate from the immutable model dataset.

A project shortlist entry stores location, crop and the search context. A scenario stores name, project, time/scenario, season, water regime, selected locations and optional price/cost/logistics assumptions. Opening an economic scenario restores those assumptions. Evidence references location and crop with source type, date, note and optional observed yield/CSV filename. Adding evidence does not change model scores or claim model validation.

The Team interface is a demonstration of Owner/Admin/Analyst/Viewer roles and project scopes. It does not implement actual authentication, server-side authorisation or email delivery.

## Global context and geolocation

The 24 clusters cover India, Brazil, the United States, Australia, China, Pakistan, Turkey, Egypt, Benin and Mali. Ten synthetic AEZ classes are reused across environmentally analogous samples. Country prefixes distinguish globally unique cell identifiers.

`growingEvidence` records link cotton-producing countries to USDA references. Their scope is national, separate from cell-level synthetic suitability. `lib/growing-practices.ts` contains scoped primary-source practice guides; no source is interpreted as proof of local adoption or superior performance in a sampled cell.

The default-location algorithm and picker are in `lib/geography.ts` and `components/location-picker.tsx`. Device coordinates are processed transiently to identify nearby sample coverage, not saved to the model dataset. User-selected search geography is persisted as a country, region or sample identifier.

The full raw JSON is generated locally and excluded from Git to avoid duplicating a 65 MB derived file. The complete compressed JSON is retained in `public/data/mock-db.json.gz`. Validation can read either form.
